## 3. 核心 API

### `concurrent.futures` —— 线程池（推荐入口）

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

# 方式 1：map —— 批量提交，保持顺序
with ThreadPoolExecutor(max_workers=4) as executor:
    results = executor.map(work_func, [1, 2, 3, 4])
    # results 是迭代器，按提交顺序返回
    for r in results:
        print(r)

# 方式 2：submit + as_completed —— 哪个先完成先处理哪个
with ThreadPoolExecutor(max_workers=4) as executor:
    futures = {executor.submit(work_func, x): x for x in items}
    for future in as_completed(futures):
        x = futures[future]
        try:
            result = future.result()
            print(f"f({x}) = {result}")
        except Exception as e:
            print(f"f({x}) 出错: {e}")

# 方式 3：submit + future.result() —— 逐个等待
with ThreadPoolExecutor(max_workers=4) as executor:
    f1 = executor.submit(work_func, 10)
    f2 = executor.submit(work_func, 20)
    print(f1.result())  # 阻塞直到 f1 完成
    print(f2.result())
```

### `queue` —— 线程安全队列

```python
from queue import Queue

q = Queue()
q.put("task 1")
q.put("task 2")
item = q.get()           # 如果队列为空，阻塞等待
item = q.get(timeout=5)  # 超时则抛 queue.Empty
q.task_done()            # 标记任务完成（配合 join 使用）
q.join()                 # 阻塞直到所有任务都被 task_done
```

### `threading` —— 底层线程

```python
import threading

def worker():
    print(f"线程 {threading.current_thread().name} 工作中")

t = threading.Thread(target=worker, name="Worker-1")
t.start()
t.join()  # 等待线程结束
```

## 4. 什么时候用线程池？

```text
你有很多文件要搜索 → 用线程池
你要下载 100 个网页 → 用线程池
你要并行处理数据库记录 → 用线程池

而不是：
你只有 3 个文件 → 不需要线程池
计算密集型（纯 CPU） → Python 用多进程更好（GIL 限制）
```

## 5. 三种并发模式

### 模式 1：map（简单直接）

```python
from concurrent.futures import ThreadPoolExecutor

def search_file(filepath):
    """在单个文件中搜索关键词"""
    content = filepath.read_text()
    return str(filepath) if "keyword" in content else None

with ThreadPoolExecutor(max_workers=4) as pool:
    results = pool.map(search_file, file_list)

matches = [r for r in results if r is not None]
```

适用场景：每个任务独立，不需要共享状态。

### 模式 2：生产者-消费者（用 Queue）

```python
from queue import Queue
from threading import Thread

def worker(q):
    while True:
        item = q.get()
        if item is None:  # 毒丸：退出信号
            break
        process(item)
        q.task_done()

q = Queue()
# 启动 worker 线程
threads = [Thread(target=worker, args=(q,)) for _ in range(4)]
for t in threads:
    t.start()

# 主线程产生任务
for item in all_items:
    q.put(item)

# 等待所有任务完成
q.join()

# 发送退出信号
for _ in threads:
    q.put(None)
for t in threads:
    t.join()
```

适用场景：任务持续产生，worker 一直在后台运行。

### 模式 3：`as_completed`（先完成先处理）

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

with ThreadPoolExecutor(max_workers=4) as pool:
    futures = {pool.submit(search_file, f): f for f in files}
    for future in as_completed(futures):
        result = future.result()
        if result:
            print(f"找到: {result}")
```

适用场景：想实时看到结果，不用等全部完成。

## 6. 最小可运行例子

```python
from concurrent.futures import ThreadPoolExecutor
import time

def slow_square(x):
    time.sleep(0.5)  # 模拟耗时操作
    return x * x

# 串行：4 × 0.5 = 2.0 秒
# 并行（4 线程）：约 0.5 秒
with ThreadPoolExecutor(max_workers=4) as pool:
    results = pool.map(slow_square, [1, 2, 3, 4])

print(list(results))  # [1, 4, 9, 16]
```

## 7. 实验任务

### 任务：多线程文件搜索器

写一个 `search.py`，递归搜索目录中的所有文件，找到包含关键词的文件。

```bash
# 搜索当前目录
python search.py ./ keyword

# 指定线程数
python search.py ./ keyword --workers 8

# 指定文件名模式
python search.py ./ keyword --glob "*.py"

# 输出结果
python search.py ./ keyword --output results.txt
```

要求：
1. 主线程用 `pathlib.rglob` 扫描文件列表
2. 用 `ThreadPoolExecutor` 创建线程池
3. 每个线程搜索一个文件（读文件、搜关键词）
4. 输出匹配结果，统计耗时

### 进阶挑战

用 Queue + Thread 实现生产者-消费者模式：
- 一个生产者线程扫描文件，不断放入队列
- N 个消费者线程从队列取文件、搜索
- 支持实时输出（找到就立即打印）

### 更进一步

比较两种方式的性能差异：
```bash
time python search.py ./ keyword --mode serial
time python search.py ./ keyword --mode pool --workers 4
```

## 8. 常见错误

| 错误 | 原因 |
|------|------|
| 线程不安全的数据共享 | 多线程同时写同一个 list/dict |
| 忘记 `join()` | 主线程退出了但子线程还在跑 |
| GIL 导致性能不升反降 | Python 多线程不适合 CPU 密集型 |
| 线程池不关闭 | `ThreadPoolExecutor` 用 `with` 自动关闭 |
| 死锁 | 两个线程互相等待对方释放资源 |
