## 1. SQLite：执行语义问题已确认

`round6_bucket/src/e789.py:334–341`先调用整批`exe.run(...,mode=2)`，再对`acc`逐项执行SQL。

`e789.py:132–137`在前一个批量阶段依据`member[x]`标签插入负缓存。最新VLDB实验文字却说SQL返回无记录后才插入。两者不一致。

准确定位：**批量、标签驱动Filter/Cache模拟＋真实SQL调用的合计计时，不是逐query在线SQL反馈驱动的路径。** 这本身不推翻FP/调用次数：在静态成员集且标签与DB一致时，模拟状态可能相同；但计时顺序、运行时交互开销与描述必须纠正。严格交错重测仍未完成。

## 5. Algorithm1：构建权重与最终评分混同，已确认

最新`vldb/sections/method.tex`先计算`w=M^SA(epsilon_old,S)`，再用FastPLBF输出的`epsilon_new`与旧`w`相乘。

实际`ra5.py:85–89`重新计算：

```text
w_build ← cache-aware allocation weights
(R, epsilon_new) ← FastPLBF(n, w_build, remaining_bits)
M_score ← M^SA(epsilon_new, S)
pred ← sum_i epsilon_new_i * M_score_i
```

构建权重仍需保留floor和无重复snap语义。这个差异首先是描述修正；若只改伪代码以符合已有实现，不需要把全部实验重做。
