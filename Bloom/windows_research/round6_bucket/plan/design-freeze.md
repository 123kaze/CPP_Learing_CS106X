# 第六轮：方案 D（按实际桶负载精算），预先声明与冻结（2026-10-29）

## 动机（只用第五轮的开发数据）

第五轮在小 key 池上输给网格。诊断见 `round5_dp/results/diagnosis_small_pool.md`：BF 一侧的预测是准的，问题在缓存一侧，有两种情况：
- 低负载时，组相联溢出是随机的跳变：只要有一个桶挤进 5 个以上的 key，就会凭空多出约 750 次误报；
- 高负载时，Che 近似有百分之几的误差。

方案 D 在第五轮的全部 148 个 E3 案例上离线验证过：选中实测最好候选的比例从 39% 升到 61%，1 万和 10 万池上对网格的中位数从 1.06 降到 1.00。真实轨迹上没有改善（0.976 → 0.982）。这些是开发数据上的结果，只说明 D 值得试，不能作为最终证据。

## 方法（RA6，代码 `src/ra6.py`）

1. 用第五轮冻结的 `ra5.candidate_table` 算出全部（树数 × 缓存比例）候选的 RA4 预测并排序；
2. 取前 TOPK=5 个，逐个建出结构（DP 分配用 RA4 的权重，并插入 BF）；
3. 对每个结构，找出学习期见过的 key 里哪些是它的误报，用 `cache5` 的桶函数把这些 key 分到各桶，每个桶用桶内 key 的 Good–Turing 速率单独解 Che（每桶 4 个槽，T 二分 60 次）；没见过的 key 的尾段查询沿用期望值处理（ε_i·G_i，NEW_MIX=0，用 RA4 自己的连续区域 FPR），占用按桶平均摊开；
4. 选预测最小的候选（平局时按 RA4 的排名），直接部署第 2 步已经建好的结构。

- 不需要学习期轨迹，只用 RA4 本来就保存的逐 key 计数。
- 无重复时，每个候选的预测都等于 RA4 的，选择也就等于 RA4 的，即等于 Gama。COD 256KiB 短流上已核对：每key一次 3,725 = 3,725，全新对抗 1,070 = 1,070。
- 敏感性：同时报告 TOPK=3 和 TOPK=10（RA6-top3、RA6-top10），共用同一张候选表和同一批建好的结构。
