# Gama 论文原始数据源上的重新评估（2026-11-01）

本轮不修改冻结 RA6。区分“同一个公开原始数据源”与“作者论文处理后数据/划分的精确复现”。

## 数据可得性

- 官方仓库当前版本、历史 dataset 路径及公开分支中没有 `url_train/test/query.csv`、`Train/Test/Query_COD.csv` 或 Yelp 处理后的 CSV。没有公开 release 数据资产。
- URL 使用作者 README 指向的 Kaggle `sid321axn/malicious-urls-dataset` v1。本机原始文件 651,191 行：223,088 恶意、428,103 良性。论文表 1 的恶意数相同，良性数为 428,118，差 15 行，不能假造补齐。
- COD 使用作者 README 指向的 Kaggle `hari31416/celestialclassify` v1。本机 `train.csv` / `test.csv` 文件大小与 Kaggle API 报告的 2,058,444,368 / 1,029,217,422 B 相符。原始数据共 600 万行，不擅自抽样凑论文的 2,498,077 / 2,980,291。
- Yelp 官网需要获取许可数据；作者过滤规则、负例生成及词/区域 embedding 文件不齐。不能换成任意 Yelp 分类任务冒充该数据。此项阻塞原因写进数据审计，不声称完成。

## 预处理与协议

- URL 执行官方提交 `27a454a` 的 `embedding_gene/url_embedding.py`，只替换输入/输出路径；`tldextract` 使用随安装包的离线 suffix snapshot，记录依赖版本。保留原脚本的 `www.` 正则归一化、特征和整行去重行为。处理后若发现同一 key 多标签，先报告；最终 AMQ 数据按 key 唯一并剔除矛盾 key，明确这不是作者的未知最终划分。
- COD 保留公开原始光谱/光学数值特征，不将 objID 当特征（这是 key）；缺失/非有限值情况单列；galaxy 为成员、star 为负例。
- 两者按稳定 key 哈希划分：成员 50% 训练；负例 10% 训练、10% 验证、80% 测试，完全对齐两种方法。不使用测试负例训练或选择。
- 预算：64/128/**192**/256/320 KiB；论文表 2 的“196”列与正文的 64 步进不一致，采用正文与图 7 的 192。
- 作者 G-LBF 与 G-PLBF 直接调用官方训练/搜索/BF 构建代码，只适配数据路径、预算与结果记录；不修补数值/算法异常来强迫成功。G-LBF 的阈值/抽样计算若有问题也如实记录。
- RA6 从头训练原参数 200 树，选择规则不变。查询负载：`每key一次`（测试负例不重复）、`zipf1.0-全部`（1000 万条）；前 25% 学习、后 75% 冷缓存评估。作者过滤器按同一尾段重放。全测试负例池逐 key FPR另外单列，避免将热点加权 FPR与论文静态 FPR混用。
- 系统时间单线程、batch=1000，包含实际模型推理/过滤器查询，构建从头计时。每个数据/预算/方法 3 次独立训练和构建；不复用已选模型。
- 原样 BF目标预算、实际后端位图和RA6预算外成员索引分列。这是作者实现与RA6实现的系统比较，不能把语言/布局差异解释为算法消融。

## 运行安排

`round7_original_e2e` 的8设置3次完整端到端实验先串行完成；本轮仅先准备数据，避免两个计时任务互相施加载荷。完成后串行执行本轮。

代码在 `src/`，数据及依赖在独立 `data/`、`deps/`（不提交）；数据来源/计数、运行日志及结果报告提交时只含审计和数值，不包含版权 PDF。
