# 结论：不用成员索引的 64 位指纹缓存（2026-11-03）

逐项数据见 `report.md`：第一至四节是主表，第五节是分解。

## 做了什么

审稿人指出：RA6 的缓存插入要查成员哈希索引（每个成员 8 B），而这份索引不在过滤器预算内。

- **RA6-fp64**：每个缓存条目改存 key 的 64 位哈希指纹，查询时 64 位全部相同才算命中，插入不再查索引。除此之外与原缓存完全相同：
  - 分桶函数相同；
  - 都是 4 路 CLOCK；
  - 打包数组和字节记账相同。
- **运行方式**：冻结的 RA6 一行不改，只把引擎用的缓存模块换掉。候选表、槽位数、按实际桶负载的预测和回放看到的都是指纹缓存。
- **范围**：与第六轮主表相同的 30 个设置、1146 个案例，查询流完全相同。
- **检查**：
  - 同一脚本换回原缓存时，逐行复现第六轮的结果；
  - 在 F = 40 位、安全长度全设为 40 的条件下，指纹缓存与原缓存的每个计数逐个相同（`src/test_cache_fp.py`）。

## 结果

| | RA6（带索引） | **RA6-fp64（无索引）** |
|---|---:|---:|
| 逐案例误报 / Gama（中位，不含探测重放，748 个案例） | 0.088 | **0.097** |
| 不比 Gama 差的案例 | 100% | 99% |
| 按总量不比 Gama 差超过 1% 的设置 | — | 29/30 |
| 无重复负载与 Gama 逐位相同 | 140/140 | 140/140 |
| 相对带索引版，逐案例中位 / 最坏 | — | 1.050 / 2.34 |
| 预算外内存 | 成员哈希索引 8 B/成员 | **无** |
| 假阴性 | 严格为 0 | 实测 0，上界 ≤ 2.4e-15 / 次成员查询 |

- 30 个设置中唯一"差于 Gama"的是 mawi2022 128KiB★：误报 1 对 0。这是高预算设置，误报只有个位数，应按绝对值读。
- 按总量看，除误报只有个位数的★设置外，大多数设置比带索引版多 0%–21%。最差的三个：

  | 设置 | 比带索引版多 |
  |---|---:|
  | URL 64 | 55% |
  | Shalla 1024 | 39% |
  | COD 256 | 29% |

- 假阴性的检查方法：在每个案例的最终缓存状态上，用全部成员逐个查询，被误判为"已缓存的负例"的成员数合计为 0。

## 差距从哪里来

方法：对第六轮 RA6 选出的同一个结构，在同样缓存字节下分别换成三种缓存，每个案例的 idx 都复现了第六轮的误报数。

| 不含探测重放，逐案例中位 | 比值 |
|---|---:|
| 前缀泛化（完整 40 位匹配 / 带索引） | **1.000** |
| 槽位变少（64 位指纹 / 完整 40 位匹配） | 1.022（10 万 key 池 1.158，真实轨迹 1.110） |
| 配置不变，只换缓存 | 1.022 |
| 按指纹缓存重新选配置（RA6-fp64） | 1.049 |

1. **差距全部来自槽位变少。**
   - 64 位指纹的条目更宽，同样字节下槽位数是原缓存的 68%（中位，范围 50%–70%）。
   - 原缓存按"安全前缀"匹配，理论上一个条目能顺带挡住同前缀的其他误报 key，但实际作用为 1.000，可以忽略。
   - **所以索引带来的只是严格零假阴性，不是更高的缓存命中率。**
2. **工作集卡在两种槽位数之间时会出现断崖。** 探测重放最坏的 17 倍（配置不变）就是这种情况。
3. **重新选配置反而更差。** RA6-fp64 按指纹缓存的槽位数重新选择（中位 1.049），不如直接沿用带索引时选出的配置（1.022）。差距里约一半来自重新选择时的预测误差，而不是缓存格式。探测重放的最坏情况 162 倍也是选择造成的：学习期没有重放，预测器看不到这类负载。

## 对论文

- 可以回应审稿人：有一个不需要任何预算外内存的部署方式。它保留了对 Gama 的绝大部分优势（误报中位是 Gama 的 0.097 倍，带索引版是 0.088 倍）；代价是槽位少约 1/3，误报中位高约 5%；假阴性为概率性的，约 1e-15 量级。
- "零假阴性"只适用于带索引版，两个版本要分开写。
- 不要声称安全前缀或索引提升了缓存效果。
- 第七、八轮对作者原版 Gama 的对比用的是带索引版。指纹版在那两轮 Zipf 负载上的结果**没有跑**，不能直接沿用。

## 没做的

- 更短的指纹（例如 48 位）：槽位更多，假阴性上界随之变大，约为 槽位数 × 2^-48。这样可以画出"假阴性概率 vs 误报"的权衡曲线。
- 用带索引时选出的配置部署指纹缓存（上表的 1.022）：它不需要索引就能部署，看起来比重新选择更好。但它没有在独立数据上检验过，不能直接当作新方法。
