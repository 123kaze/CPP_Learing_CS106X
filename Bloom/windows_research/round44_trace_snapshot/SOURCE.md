## Changes made for this experiment

- Select the first three named sample files by a rule fixed before downloading, not by model outcome.
- Retain `get`/`gets` requests in their supplied record order; do not sort timestamps or synthesize request frequencies.
- Build a new **immutable seen-key checkpoint directory** from the first25% of these GET requests.
- Interpret later requests as exact-membership queries to that directory. This label is generated by the new task, **not an original Twitter backend result**.
- Split negative training/validation keys only from the next25%learning interval; keep remaining eligible tail requests in original order.
- Derive24fixed lexical features from the complete anonymized key itself; discardclientid and do not use response value sizes/TTL as labels.
- Compute aggregate diagnostic/method results. Full anonymized keys and source client columns are not republished by this artifact; downloaded originals and prepared arrays stay locally ignored.

Source documentation describes timestamps as when the cache receives a request, and anonymization as preserving namespace structure. It does not establish how these particular sample files were chosen or prove an uninterrupted fully ordered production recording. The experiment reports reversals and does not upgrade source uncertainty into a guarantee.

## What the transformed task can and cannot show

The prefix-only catalogue makes static exact-membership truth reproducible without inferring backendNotFound from cache behavior. It is relevant to a checkpoint seen-before/deduplication lookup experiment on real request identities and repetition patterns.

It does not show that the original cache or database lacks any particular key, that the original full member set is known, or that its original operators need a learned filter. Any advantages are limited to this explicitly constructed directory task and the measured accounting/deployment. More general production claims need independently verified application semantics and end-to-end costs.

Download receipt, exactbyte lengths, Gitblob identities and SHA256 hashes are in [downloads.json](results/downloads.json). Original files were obtained via public HTTPS into three separate new empty directories; no access restrictions were bypassed.
