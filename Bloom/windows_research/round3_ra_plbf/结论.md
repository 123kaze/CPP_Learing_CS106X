# 方法 C（RA-PLBF）结论（2026-10-29）

完整数字见 `results/main/report.md`，方法与冻结记录见 `plan/design-freeze.md`。

- **规模与口径**：20 个设置（7 个数据集），合成负载 10M 查询×5 种子×全部负载，真实轨迹完整一次，共 197 个"设置×负载"。
- **与第二轮逐行一致**：共享基线（Gama、误报流模型、学习期网格、固定 48 树＋缓存）3,787 行，与 Windows 第二轮完全相同，0 行不同。所以这里的数字可以和第二轮报告直接对照。

- **按负载：** 197 个"设置×负载"里，对网格的比值中位数为 1.000，49% 不比网格差，18% 差 10% 以上。
- **对比误报流模型（第二轮的贡献 3）：** 中位数 1.246，最坏 651×。第二轮里最严重的几处坏例，RA 都追平或超过了网格：COD 1024 误报流模型 118×、RA 0.94；URL 128 是 33×、RA 1.01；URL 256 是 22×、RA 0.64；caida_flow 16/24 是 3.6–4.2×、RA 0.99。

**唯一明显的坏例：Caida 1024 的探测重放负载**（RA 23,261 对网格 2,656，8.8×）。
- 被重放的 key 池在尾段持续扩大。RA 对 2048 槽和 4096 槽的预测只差 0.15%，于是选了 2048 槽，实际却在抖动。
- 这是"预测平坦、真实结果有悬崖"的问题。改选择规则等于在评估集上调参，所以冻结的方法没改。可以作为下一轮预先登记的改进：预测接近时偏向更大的缓存。

**漂移负载（冻结前列出的风险）：** 完整规模下没有出现开发集里的问题，11 个设置中 RA 和网格互有胜负，例如 caida 128 为 1.87M 对 2.30M、shalla 1024 为 184k 对 159k。原因是 10M 查询下学习期已经能看到难负例的重复；开发集只有 1M 查询，看不到。

## C5 判据

**多数设置下不比网格回放差：满足。**
- 按每个设置的负载比值中位数：RA-PLBF 13/20，RA-PLBF+G 12/20。
- 按总量：RA-PLBF+G 15/20。

**任何设置下都不比 Gama 差：按总量满足，按逐负载的严格标准不满足。**
- 按设置总量，每个设置都远好于 Gama。
- 在 197 个负载中，有 10 个 RA-PLBF+G 略多于 Gama，全部是没有重复可利用的负载（每key一次、全新对抗、uniform-全部）。超出幅度：
  - caida 128 全新对抗：37,189 对 35,872，+3.7%；
  - url 256 全新对抗：1 对 0；
  - 其余 8 个都在 +1% 以内。
- 设计表里的判据原文是"不比 Gama 差超过草图开销"。是否按这个口径算满足，需要和导师一起判断。

## C3：估计准确度

- **总量预测/实测的中位数：** 合成负载上为 1.00–1.49，73–94% 的案例在 2 倍以内；真实轨迹上为 0.88–2.39。
- **段级预测**（按误报加权、2 倍以内的比例）：Shalla 和 URL 128 达到 83–96%；COD 1024 和 URL 256 为 0%。这两个设置的总误报只有几百次，分到每段只有个位数到几十次，所以段级的比值没有意义。caida_flow 16/24 的总量高估了 2 倍以上，但选出的配置仍然好于网格。
- **结论：** 用来排序候选配置足够可靠，但不能声称"每段预测都准"。

## C4：消融（对 RA-PLBF 的比值，中位/最坏）

| 消融 | 结果 | 说明 |
|---|---|---|
| 去掉重复折扣（RA-NoRepeat，退化为学习期 PLBF＋缓存） | 合成中位 1.00–1.12；真实轨迹 MAWI 上差 1.4–2.6× | **分段重复折扣是有效部件** |
| 只选全局缓存、分配沿用验证集权重（RA-GlobalCache） | 中位 1.00–1.20，最坏 2.5×；MAWI 上差 1.01–1.15× | 分段选择有中等收益 |
| 经验频次换成每段 Zipf 拟合（RA-Zipf） | 中位 1.00–1.21，但最坏 753×（COD 1024）、2526×（URL 256） | **必须用经验频次** |
| 时序自检护栏（+G 对比不加护栏） | 最坏从 11.7× 降到 8.8×；COD 256 全新对抗从 11.7× 降到 1.0× | 有效；但在误报个位数的设置（Caida 1024）偶尔误判 |

## 开销

- **选择耗时：** RA-PLBF 每次 0.2–1.8 秒，带护栏 0.4–3.6 秒。网格回放（第二轮已做了等价加速）为 0.24–3.95 秒，误报流模型为 0.03–0.46 秒。所以 RA 的卖点不是"选得更快"。
- **学习期状态：** 逐 key 计数为 1.0–1.9 MB，学习结束后释放。网格需要保存约 20MB 的学习期轨迹。部署状态都在同一物理预算内。

## 对论文形态的含义

- **方法 C 成立，可以作为方法核心：** 它是一个真正的分配算法，效果与学习期网格回放持平（中位 1.000），在所有真实轨迹上更好，并且修掉了误报流模型的全部灾难性坏例。
- **需要如实写明三点：**
  1. 逐负载的严格"不比 Gama 差"不成立，最多超出 3.7%；
  2. 存在缓存容量悬崖导致的坏例（Caida 1024 探测重放，8.8×）；
  3. 段级预测在误报很少的设置里不可靠。
