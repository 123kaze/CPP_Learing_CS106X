# 第十四轮：主表八设置的新实现端到端计时（2026-11-10）

用户要求优先启动新实验，英文 README 与 DOI 后置；本轮不改论文、旧冻结代码或原版 Gama 算法。

## 固定设置与方法

复用第七轮表格的八个设置：caida_flow 24、url 128、mawi2020_flow 24、mawi2021_flow 24、mawi2022_flow 24、caida 256、shalla 1024、cod 1024（KiB）。合成流 zipf1.0-全部 seed0，真实流保序，原前25%学习／后75%冷缓存评估。输入固定件与原版 CSV 只读，不重新生成或改切分。

每个设置三个独立重复，每个重复在新进程从头运行：RA6-loop、RA6-leaf、作者原版 G-PLBF，共72个正式进程。顺序按重复轮换：(loop,leaf,gama)、(leaf,gama,loop)、(gama,loop,leaf)，使三方法各占一次每个位置。全程串行、单线程，不为了墙钟时间同时挤占内存。

先以 caida_flow 24KiB 各跑一次三方法正确性 pilot（另3进程），通过后自动开始正式实验。pilot不并入正式计时。失败记录保留，任何失败非零退出，不自动重跑；尤其内存压力终止需用户许可。

## 新实现与检查

新 RA6 worker 由第七轮复制，只改变前缀打分分支及计时外校验：使用已冻结第十三轮 pred_leaf helper，32768行一块，200棵31叶子树，float64依原树序累加14个前缀。训练参数、只打分成员／验证负例／学习期不同key、DP、候选空间、Che、选择及原生查询代码不变。

原版直接调用第七轮 gama_worker.py，训练／贝叶斯搜索／FastPLBF／bloom_filter／pickle口径原样保留，不拷贝或改写其搜索代码。新原版测量与新RA6同期串行进行，不拼接旧原版时长声称新速度比。

每对RA6检查模型、14个分数摘要、配置、预测FP、BF位图、可执行模型数组、全负例池原生判定、尾段／混合batch／混合scalar的FP/FN、cache hits/model calls全部一致。每个新RA6还必须复现冻结主表配置/误报；三方法各与第七轮相同重复的配置/计数逐一核对。若不一致停止，不放宽阈值或挑选重复。

## 度量与边界

保留原第七轮全部阶段：train_to_ready（不含读取/JIT/校验/查询输入准备）、全尾段实际查询、20万混合batch=1000、2万混合batch=1、train_to_ready+全尾段查询。每次都真实树遍历和BF/缓存访问，不用静态FP数组替代计时查询。

额外hash与全负例池核验放在ready计时之后，不计入服务查询耗时；整个进程墙钟包含这些校验，不能当纯构建成本。峰值RSS覆盖全进程，不保证因分块而普遍下降。

每个设置按3次配对比值取中位，原始次数、范围和所有不利结果保留。三次是同一数据的计时重复，不是独立数据种子；不新增显著性或普适性主张。原版BF内存表示／语言／查询实现、预算外成员索引等差异照旧披露，本轮不是同内核的算法消融。

源代码在plan/freeze.json冻结，输入与双环境版本在results/manifest.json核验。后续报告只能读取正式完成结果，不修改已测代码或挑选有利运行。
