## 资源与正确性

资源表区分 Filter 和 Backend。index 格式需要的成员哈希索引是 `8*n` 字节加 ndarray 头，不能说任何后端原生免费提供；fp64不需要该验证索引，但并非严格零FN。

- index30行：直接使用历史组件字段，同时检查保存模型的真实数组和布局。
- fp6430行：历史CSV只有total/cache。重建模型/布局字节，再由总量扣除已知项得到BF负载，逐行明确标注“derived / NOT fresh BF build”。
- 后端完整key/记录内存没有被测成0；训练和候选工作区不属于部署Filter预算，但仍是实际资源成本。
- 人工注入一个“不同语义key、相同64位hash”的表示碰撞：verified-prefix计算安全长度65而跳过插入，成员不被拒；fp64则会命中并误拒成员。不是声称找到了真实哈希碰撞。
- fp64在理想、非对抗hash条件下每个成员查询的上界为 `min(1,S/2^64)`，S取驻留数量或容量保守上界。不是整个运行寿命或对抗查询保证。
