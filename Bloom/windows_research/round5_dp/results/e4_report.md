# E4：构建时间与内存分解（单线程，JIT 预热后取 5 次中位数）

硬件：Apple M4 Pro，线程数 1。每个数据集取中间档预算，合成负载用 zipf1.0-全部（种子 0），真实轨迹用完整轨迹。

计时口径对所有方法相同：
- 网格回放 = 建全部约 150 个候选（DP + 插入 BF + 查询学习期出现过的 key）+ 在学习期上精确回放（带提前停止）；
- Gama = 每个树数各跑一次 DP 估计 FPR；
- RA4 = 学习期逐 key 计数 + 全部候选的预测；
- RA6 = RA4 的预测 + 建前 5 个候选 + 按桶精算（选中的结构就是这 5 个之一，不用再建）。

## 结论

- **选择时间：** RA6 在 8 个设置上都比网格回放快，是网格的 1/1.8 到 1/5.4。差距随候选结构的构建成本增大：成员越多（COD、Shalla 约 300 万）、测试 key 越多，网格要建的约 150 个结构就越贵。RA6 比 RA4 只多 0.04–0.33 秒。
- **内存：** 在合成负载的大 key 集合上（24 万–63 万个不同 key），RA6 选择阶段的峰值约为网格逐个建版本的 1/2、全部常驻版本的 1/3 到 1/5，而且不需要网格那份 7–20MB 的学习期轨迹。但在真实轨迹上（6 万–12 万个不同 key），RA6 的峰值（13–20MB）和网格相当甚至更高：RA 每棵树都要在 1000 个分数段 × 161 个 T 值上建表，这部分不随 key 数缩小。算上网格的轨迹之后，两者大致持平。所以论文里只能写"不需要保存学习期轨迹，大 key 集合上选择阶段内存更小"，不能笼统地写"内存更小"。
- **训练和打分：**
  - 训练 200 棵树是所有方法共享的成本，COD 上单线程要 62 秒。
  - 成员和验证集在各树数下的打分也是共享的，53–96 秒（合成负载）。
  - 学习期 key 在各树数下的打分只有网格和 RA 需要，Gama 不需要。它要 4–15 秒（合成负载），比 RA6 的选择本身还贵。所以相对 Gama，RA6 多出的成本是"给学习期的 key 打分"加上"选择"，合成负载上大约 7–18 秒；网格也要付同样的打分成本。
- `RA4-fast` 的结果保留在 json 里，只作参考，因为它和 RA4 的选择不完全一致（见 `results/verify_fast/`）。
