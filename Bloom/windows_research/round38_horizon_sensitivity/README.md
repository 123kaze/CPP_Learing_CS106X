## 对照和边界

33个matched-H结果须复现旧档案：12例×两格式24行，ClarkNet-index9行。ClarkNet-fp64的9个matched配置是新补充，不是留出前验证。四种规则即使H相同也实际重新选择，相同H须逐字节匹配结构、flags和最终cache。

fp64 worker不构建或持有排序成员索引，也不计算safe prefix；建BF和最终检查仍需要成员hash数组，属于构建/验证状态。有限数据上未观察到FN不等于一般键域的严格zero-FN。

**后续勘误：[第40轮](../round40_fingerprint_assumptions/README.md)核实，当前共享BF/cache hash并按BF放行筛选条目时，仅“理想非恶意hash”不足以推出S/2^64容量界。** 本轮JSON中`fp64_ideal_hash_bound_per_query`保存的是当时这一额外独立性假设下的参考数值，不能直接作为现实现一般key域的已证明上界。冻结代码和原字段不静默修改；实际FP、预算及有限成员0FN记录不变。

本轮不改变实际尾段长度，不依据结果选H，不验证无限期开放流重建策略，不重启旧留出验证，不修改论文。H可解释为下一次计划性复核前的预计negative请求量；3L只是预设启发式。

加载、模型/score、索引、GT摘要、JIT、选择/构建、候选记录、payload复建、完整回放和成员检查分别计时。回放使用预计算flags，不是完整数据库端到端延迟。
