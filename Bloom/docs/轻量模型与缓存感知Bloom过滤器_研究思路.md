# 轻量模型与缓存感知 Bloom 过滤器：研究想法与场景分析

日期：2026-11-20

性质：讨论整理与研究设计，不是已验证的新算法、论文正文或实验结果。

范围：整理用户提出的方向，分析布隆过滤器真正需要什么，并规划最小验证路径。本次不修改冻结方法、不运行新实验。

## 0. 一句话概括

> 不再把“多少棵树”当成问题本身，而是研究：在有限内存和查询成本下，能否学习一个足够便宜的评分或路由函数，让 BF 和负缓存更有效地协同；模型不划算时，允许不用模型。

这里要同时区分三个问题：**模型有没有信息、信息值不值得付费、选择器能不能识别这个价值。**

---

## 1. 用户提出的想法是什么

### 1.1 已明确提出的方向

用户连续提出的问题包括：

1. **为什么必须用树？** 是否可以用线性模型、贝叶斯方法或更小的非线性模型，以降低训练、模型存储和推理成本？
2. **先理解数据，再训练。** 是否应该先分析特征、冗余和可分性，必要时降维，而不是直接套固定树模型？
3. **是否需要专门的学习算法？** 通用分类器未必适合布隆过滤器；能否针对这个场景设计训练目标或模型结构？
4. **保留无模型选择。** 弱模型场景不应被迫支付模型开销，应能退回普通 BF＋缓存。
5. **不能为了回退丢掉低选择成本。** 如果需要大量回放才能决定用不用模型，可能削弱原方法的主要优势。
6. **先查相关工作。** 不能把已有的轻量模型、PLBF 分区优化或经典统计恒等式直接当作新贡献。

这些方向并不等于已经决定使用某个具体网络、PCA、朴素贝叶斯或某种训练损失。用户当前要求是：先明确需求和可研究的问题。

### 1.2 讨论中提出、但尚未验证的候选方案

以下是助手提出的建议，不应写成用户已经确定的方法或实验事实：

- 先比较稀疏逻辑回归、分箱加法评分器、小型单隐层网络和小树。
- 在相同模型结构下，比较普通分类训练、面向 BF 分配的训练、进一步面向缓存残余成本的训练。
- 探索直接学习少量区域的路由函数，而不是一定先学习高精度概率。
- 将模型类型、模型容量和“关闭模型”统一纳入候选。

**分箱加法模型是优先值得试的候选之一，不是已经证明最适合的模型。**

## 2. 为什么过去一直使用树

目前沿用树模型，主要是研究设计和实现选择：

- 与 Gama 的模型及前缀候选保持一致，便于区分模型收益与分配算法收益。
- 一个训练好的树集成能提供多个前缀，方便控制模型容量。
- 树对表格特征中的阈值、区间和交互具有较强表达能力，较少依赖标准化。
- 现有紧凑模型导出、原生遍历、候选记账已经围绕树实现。

但是，**缓存感知分配的数学接口并不必须是树**。核心输入是模型分数及相应分区上的成员、负查询与重复统计；原则上可以由其他评分器提供。

需要区分：

- **原理上的模型可替换性**：并不要求 LightGBM。
- **当前代码上的耦合**：候选名是树数，部署数组是树节点，成本函数也是树表示；替换模型需要新的评分、部署和真实字节核算接口。

因此不应把树当成不可改变的研究前提，也不能声称更换模型只是改一个函数名、其他实验自动可比。

## 3. 布隆过滤器场景与普通分类任务有什么不同

### 3.1 过滤器是“避免昂贵查询”的前置结构

普通 BF 用 m 位表示 n 个成员，典型理想近似为：

`FPR ≈ (1 - exp(-k n / m))^k`。

连续最优哈希次数下，可近似写成 `exp(-(ln 2)^2 m/n)`。小预算下 k 必须为整数，位图和元数据也有真实开销，不能只用连续近似收费。

过滤器回答“不存在”时，后端请求可以省掉；回答“可能存在”时，仍需后端确认。对真实成员，正确构建和查询的结构必须保留接受路径。

### 3.2 模型自己的分类错误并非最终过滤器错误

在正确构建的 learned BF 中，后备 BF 负责覆盖模型可能拒绝的成员；在 PLBF 中，各区域 BF 覆盖路由到该区的成员。

因此：

- 不要求分类器单独达到 100% 召回率。
- 不必以分类准确率最高为最终目标。
- AUC 或交叉熵可以用于诊断，但并不直接决定同预算过滤器的 FP。
- 模型参数、预处理或路由规则一旦变化，原成员的区域归属可能改变，必须重建或一致地迁移后备结构；不能边更新模型边继续使用旧位图。

零假阴性来自**模型路由与后备过滤器的一致构建契约**，不是模型预测特别准确。

### 3.3 我们真正需要的是“有用且便宜的分离”

一个评分器可以不善于输出校准概率，却能把成员与难过滤负查询分开，从而使分段内存分配更有效。

但“只要排序好就够”也不能绝对化：有限的分数分箱、阈值、平滑和分区选择会受分数变换影响。应评价最终分段结构，而不是仅凭 AUC 推断性能。

## 4. 负缓存让目标进一步改变

### 4.1 不是所有误报都同样昂贵

没有负缓存时，某个负 key 每次被 BF 放行都需要后端确认。存在负缓存时，第一次确认不存在后，后续查询可能直接命中缓存。

因此，原始负查询频率并不等于它最后造成的后端访问成本：

- 少量可长期留在缓存的热误报 key，可能只付少数几次确认成本。
- 大量一次性负 key、冲突严重或经常被淘汰的 key，可能持续造成代价。
- 重复成员不会进入负缓存，不能把成员热点当成可被负缓存吸收的负例。

**不能简化为“热 key 都不重要”或“权重取 1/频数”。** 缓存容量、桶冲突、替换策略、顺序和未来漂移都影响实际残余成本。

### 4.2 当前框架的错位在哪里

现有流程主要是：

`按普通分类目标训练模型 → 根据重复统计选择模型／BF／缓存分配`。

模型训练本身通常不知道：

- 自己多占一个字节，会从 BF 或缓存拿走多少空间；
- 哪些分类错误能被缓存低成本吸收；
- 最后需要多少分数区域，而不是多精细的概率；
- 自己的推理时间是否超过省下的后端成本。

这构成一个值得验证的假设：**通用分类训练可能把有限模型容量花在下游并不昂贵的错误上。**

它目前只是研究假设，不能据此断言普通分类训练一定差。

## 5. 模型需要满足的实际要求

| 要求 | 在本场景中的含义 |
|---|---|
| 紧凑 | 模型、标准化、分箱边界、查表、量化参数与元数据都收费 |
| 低单查询成本 | 少量运算、访存和分支，不依赖大批量 GPU 才能快 |
| 有效分段 | 让有限区域之间的成员量与残余负查询成本有足够差异 |
| 易控容量 | 能清楚搜索几百字节、几KiB等配置，而不是模型越大越好 |
| 查询时可用 | 特征必须在后端查询前可得，不能包含未来统计或答案 |
| 可稳定部署 | 评分与区域规则固定，成员插入和查询路径严格一致 |
| 可关闭 | 没有足够收益时允许无模型 BF＋缓存；延迟研究还需 Direct 对照 |
| 不隐去学习成本 | 模型训练、标签获取、候选选择及预处理分别记录 |

一个18维float32逻辑回归的权重与偏置只有76字节，但这只是参数载荷，不是含标准化和数组头的完整模型成本。

8个特征、每特征16档、每档2字节的加法评分表只有256字节载荷，但仍要计算分箱边界、特征编号、元数据和查表开销。模型压缩或量化若改变分数，应在该部署表示下重新构建并验证过滤器。

## 6. 数据分析应该先做什么

### 6.1 先分析信息，再考虑降维

已核对的实际特征：

- TCP-only：源地址和目的地址，共2维。
- CAIDA：Time、Source、Destination、Length，共4维。
- URL／Shalla：18个URL形态特征。
- COD：数十个天文属性特征。

由此可见，PCA不是所有数据的统一答案：

- TCP-only的首要问题是特征是否有信息、地址编码是否合适，而不是维度太多。
- URL／Shalla应先看是否少数特征已足够；未必需要增加投影层。
- COD可以检查相关性、冗余、尺度与少量特征组合，再比较特征选择和降维。

PCA保留高方差方向，不保证保留成员判别信息；投影矩阵也占内存和计算。即使无需标签，PCA、标准化也应在预定训练划分拟合，不能利用评估段特征选择有利表示。

### 6.2 相同特征、相反标签是模型能力的硬边界

如果一个成员和一个负 key 输入特征完全相同，任何只看这些特征的确定性评分器都给它们相同分数。更大的树、线性模型或神经网络都不能凭空区分。

应检查：

1. 是否发生原始特征的真实重叠。
2. 是否由不合适的数值编码或float精度损失额外合并了不同输入。
3. 是否有真实查询时可取得的区分特征。
4. 没有可用信息时，是否应该直接关闭模型。

IP地址不天然适合作为连续实数做线性回归。按字节、前缀或类别编码可能更合理，但编码本身的维度、存储和泛化能力都要收费与验证。不能为了分开UDP成员和TCP负例而加入等同于标签的协议信息，再称模型解决了同协议部署问题。

### 6.3 最有用的分析产物

优先得到四类小结，而不是先画大量无目的的降维散点：

- 特征与标签重叠／编码精度检查。
- 各特征的单变量与简单交互区分能力。
- 模型容量—物理字节—原生单查询耗时—过滤器FP的曲线。
- 原始负查询质量与缓存后残余负查询质量的差异，以及这种差异能否从学习期预测。

## 7. 候选模型如何选择

### 7.1 稀疏逻辑回归：最便宜的起点

`s(x) = sigmoid(w^T x + b)`。

优点是参数少、点积简单、易核算。需要标准化或适当编码，可能欠拟合交互。

**sigmoid是单调函数，在线性点积后加它不会产生高次决策边界。** 若需要非线性，应增加显式交互／分段特征，或隐藏层，而不是仅更换输出激活。

### 7.2 分箱加法评分器：优先尝试的折中

`s(x) = b + Σ_j w[j, bin_j(x_j)]`。

每个特征可有非线性贡献，运行时分箱后查小表相加。参数和访存数可控，适合先做非常小的模型。必要时可以限制数量地加入两特征交互，但不能无限扩表。

它不能任意表达复杂交互；分箱搜索、边界存储和未见取值也有代价。**评分卡／加法模型本身是已有方法，不是我们的新发明。**

### 7.3 朴素贝叶斯：值得作为对照，不先认定最优

训练和部署可较简单，但条件独立性、连续分布形式或离散计数假设可能不匹配特征。高斯朴素贝叶斯与离散朴素贝叶斯适用输入不同。

“贝叶斯”包含很多模型；不能把这个名字直接等同于参数少、推理便宜或理论上更稳健。

### 7.4 很小的单隐层网络

例如 `s(x) = sigmoid(v^T ReLU(Wx+b)+a)`，隐藏层容量预先限定。

能学习交互，但是否比小树更快取决于单条请求、原生实现和内存布局。不能用神经网络的批量吞吐对比树的单请求延迟。

### 7.5 直接学习区域路由

可以探索 `g(x) ∈ {1,...,k}`，直接生成少数区域，而不是先训练很细的概率评分器。

这更贴近最终分区需求，但离散划分搜索可能昂贵，且容易在小负例样本上过拟合。已有分区过滤器优化和神经成员数据结构，需要具体核查重叠；不能仅换成“路由”术语就算创新。

## 8. 可能的新学习算法：新意应放在哪里

### 8.1 研究问题，而非先命名新模型

> 固定很小的模型容量，能否通过面向最终BF／缓存成本的训练，得到比普通分类训练更有用的区域划分？

模型结构可以沿用已有的小模型。真正待研究的是：**训练目标、资源约束、与分配器的耦合，以及低开销求解方式。**

### 8.2 目标一：固定内存下最小化残余FP

设θ表示评分器，a表示BF分配，c表示缓存配置：

`min_{θ,a,c} estimated_FP_after_cache(θ,a,c)`

约束为：

`M_preprocess + M_model(θ) + M_BF(a) + M_cache(c) + M_metadata ≤ M_budget`。

现有计数／Che预测可以作为起点，但并非真值；其估计偏差、跨类型校准和有限候选截断的问题不会因为换模型就自动消失。训练过程不能只优化这个近似到极端而不检查独立验证表现。

### 8.3 目标二：实际查询时间或生命周期成本

若研究系统延迟，应另定义目标：

`T ≈ Q·c_cache + N_cache_miss·c_model+BF + F·(c_backend_absent+c_feedback) + Q_positive·c_backend_present`。

这是分解思路，不是精确统一公式：成本与请求类型、缓存状态、候选及批量方式有关；无模型／无缓存时对应项应消失。模型未必对所有请求执行，成员查询也有成本，后端原生Bloom已经处理的miss可能很便宜。

考虑使用周期时再加入训练、标签获取、选择和构建成本。不能简单给每棵树加常数罚分就声称端到端最优。

### 8.4 建议的最小训练探索

固定一种轻量评分器，逐层比较：

1. 普通分类训练。
2. 根据分配后的BF代理成本调整模型。
3. 进一步根据缓存未吸收的负查询代理成本调整模型。

可从少量特征／分箱／权重的交替优化开始：固定模型求分配，再尝试模型小改动并评估分配后的目标。它是待实现的非凸启发式，不声称全局最优；每次调用分配器、统计更新和调参成本都计入。

需要防止“自己制造并反复强化自己的错误权重”：残余权重依赖当前过滤器和缓存，新模型又改变它们。必须设独立验证与停止规则，而不是在同一学习轨迹上无限循环直到结果好看。

## 9. t=0与“不劣”的正确位置

### 9.1 t=0应推广为模型关闭选项

不同模型不一定有树数。更一般的候选是：

`model ∈ {none, linear, additive, tiny_network, tree}`。

none仍是普通BF＋缓存；它不是Direct/no-filter。若目标是数据库延迟，Direct也应作为独立基线或明确允许的配置。

### 9.2 三种“不劣”不能混在一起

- **扩大候选集合的真实最优值不劣**：数学上成立。
- **学习期实测选择不劣于保留基线**：精确比较同一学习目标可以保证，但需要计入比较成本。
- **任意未来查询上同时不劣于所有基线**：仅凭过去数据不能无条件保证。

低成本预测式门控要解决的是校准与选择可靠性，不是只把none放进列表。若考虑置信区间或后半段验证，必须说明相关性、候选后选择和未来假设，不能随便添加阈值就称为高置信保证。

### 9.3 既有探索提供了什么教训

- 预测式zero-tree扩展能部分改善TCP-only，但候选可能被初筛或精排误判。
- 精确学习回放门控在已测矩阵上实现对BF＋缓存无尾段退化，同时仍有相对RA6的未来退化，且增加选择成本。
- 共享回放优化因已有收益不足以支持继续投入而主动终止，未把不完整计时当成正式结论。
- KL／Dirichlet受限静态诊断能在四个TCP设置中选择零树，但未修复两个对抗失败；同树静态EB对照有24改善、23退化。它不是完整缓存感知方法的终局验证。

这些结果说明应减少同时变化的部件，而不是把多个未验证启发式叠起来期待互相抵消问题。既有无重复退化、预算和速度性质也不能自动转移到新评分器／新训练算法。

## 11. 推荐实验顺序：先证明值得做，再增加复杂度

### 阶段A：只换评分器

固定原数据划分、特征、统计修复版本、缓存格式和分配规则。候选包括none、稀疏逻辑回归、一个小型分箱加法模型、一个小网络和受限小树。

记录每种评分器的：

- 完整部署字节（含预处理）与单请求原生评分耗时；
- 相同总预算下最终FP，而不只看AUC；
- 模型训练、选择和最终构建成本；
- 全成员接受与部署／构建一致性。

先选少量预定弱／强模型场景，不使用holdout调容量。**目的不是挑一组所有模型中最好的结果，而是判断低容量评分器能否提供有价值的过滤信息。**

### 阶段B：同模型、同容量，只换训练目标

普通分类损失、BF感知目标、BF＋缓存感知目标三组并排。预处理和模型超参范围固定；同等或明确披露的训练搜索预算；最终评估段不参与选择。

这个比较才能识别新的训练方法贡献。若三者没有稳定区别，就不能以换了模型为由声称缓存感知学习有价值。

### 阶段C：验证模型关闭与选择成本

保留none对照，分开评估预测门控和昂贵参考选择。报告所有被选择／未选择模型的代价及剩余退化，不从评估结果事后指定赢家。

### 阶段D：冻结后再验证泛化或系统效果

开发集实验通过后，冻结训练、特征和门控规则，再找未参与设计的数据或时间段验证。已经看过的MAWI-24不能重新当作新模型的独立holdout。

若声称系统加速，应使用真实反馈链和后端原生优化，包含Direct及BF＋缓存对照；不能靠关闭内部Bloom、注入延迟或只报减少的FP替代真实收益。

## 12. 什么结果值得继续，什么结果应该停止

值得继续的证据：

- 轻量模型让出显著内存／计算，同时保留有用的分段能力。
- 在同模型容量下，下游成本训练比普通分类训练更好，而不是仅有更复杂模型获胜。
- 缓存感知训练在重复负查询上有额外收益，无重复／漂移控制的代价可解释且完整披露。
- 训练和选择成本能在明确使用周期内摊销；若不能，说明仅适合离线静态构建。

不够充分的证据：

- 只在开发集上出现一个“0负”表。
- 只比大树快，却没有同等预算的普通小模型对照。
- 只比较分类指标或条件理论代理，不比较实际部署FP。
- 只报告模型权重字节，忽略特征转换和索引。
- 用候选数很多的昂贵调参得到好模型，再忽略训练／选择成本。

如果普通小模型已经达到同样结果，应接受简单方案；如果轻量模型完全没有信息，则应回到特征或无模型结构，而不是为了新算法继续加层次。

## 13. 当前建议与未决定事项

**建议优先级：数据／特征诊断 → 轻量评分器替换 → 同模型下的任务目标训练 → 冻结后的独立验证。**

尚未决定：

- 是否采用分箱加法模型作为首个实现。
- 训练目标先只优化FP，还是同时研究查询延迟。
- 具体模型预算、分箱／交互容量、候选集合与训练搜索预算。
- 最终采用统计型门控还是付费验证；不能预先承诺两者优势同时满足。

本文件没有批准或启动上述实验，没有更换主方法，也没有修改论文。下一步如果实施，应新建轮次并预先冻结最小比较，而不是直接覆盖原RA6与Gama对照。
