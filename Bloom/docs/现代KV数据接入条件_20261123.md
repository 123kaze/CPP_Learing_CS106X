# 现代KV数据接入条件：不能用缓存命中日志替代存在性证据

2026-11-23。关联[逐项计划](三项部署问题_逐项实验计划_20261123.md)。当前未取得可核验的新现代生产KV输入，不能给该项目打勾。本次公开检索未定位匹配数据；部分请求因工具/域名核验不可用失败。没有下载受限数据、换工具绕过访问限制或寻找生产凭据。

## 最小可用材料

需要来自同一授权工作负载的：

1. 数据/采集说明：时间范围、采集方式、采样/匿名化、许可与可发布范围。
2. 精确成员快照：原始key字节（可用base64编码），快照版本/时间。若只给hash，要明确真实key域就是该值还是已压缩表示，不能混淆精确key和fingerprint。
3. 有序请求：稳定的顺序编号、key、操作类型；若是只读固定快照，明确整个评估窗口不写入。若有更新，需完整更新日志与版本一致性协议，不能套静态证明。
4. 真实GET结果：found/not-found来自精确KV存储，不是上层cache miss；区分超时、权限、连接失败、损坏与不存在。不能把错误当negative。
5. 可学习特征的可用性：query时能独立从key/请求提取，不用状态码、found、未来频率、响应大小、后验ID标签或不可在query时取得的信息。

只提供原始匿名hash时，重复请求仍可测cache价值，但往往丢掉可学习结构；不能用hash数值作为“语义特征”来宣称学习模型价值。数据脱敏必须保留一致性，禁止尝试反匿名化。

## 协议在效果之前冻结

- 先冻结成员语义、开发/学习/尾段边界、原始顺序、key互斥训练/验证/测试分配及可用特征。
- 在开发/learning区检查规模、正负特征重叠、AUC、重复度和不同score-region重复差；资格不是按tail RA是否赢来决定。
- 所有合格数据都进入固定预算/seed五方法及BF强基线矩阵；资格失败说明原因，不降低门槛。
- 冻结后第一次看tail即使RA输也保留；不能把同一日志多个seed称多个独立负载。
- 严格0FN方案优先精确key缓存或明确计费的verified-prefix；fp64可另列，但正确性契约不同。
- 后端必须是授权、隔离的测试环境；不需要生产凭据，不在聊天中提供密码或真实客户标识。

## 第41/42轮为什么不能替代这项材料

第41轮重建ClarkNet真实HTTP原始key并核验顺序，解决精确cache/辅助预算对照。第42轮用这些key驱动本机SQLite精确BLOB GET，测服务路径与成本。二者都有实质用途，但原始数据仍是1995年HTTP、成员目录使用全日志回溯稳定子集；改变backend不改变数据来源与成员构造。

如果没有以上数据或授权环境，正确结果是保留“现代生产KV证据缺口”，而不是生成一套偏向模型的synthetic查询再改名真实工作负载，也不是将站点404直接说成数据库生产GET。
