# 更大真实请求轨迹：元数据筛查记录

2026-11-22。此处只记录已经查到的格式、可访问性与边界，**尚未下载新轨迹、训练模型或得到新的效果结果**。不能把“请求很多”直接当成“成员目录大、模型有价值”。用户目前选择先做本机TCP后端对照，见第35轮。

## 筛查要求

优先寻找可复现、保留请求顺序和可用key特征的真实轨迹。若研究“缺失资源查询”，需要真实HTTP不存在响应或独立可信成员目录；不能把cache miss、零字节、数据库更新标记当作nonmember标签。

正式采用前还要检查：唯一成员/key规模、标签冲突、训练/验证与尾段隔离、真实负查询重复度、score region差异。不得看到尾段RA胜负之后再挑数据/预算；没有正结果就如实保留。

## 特别注意

- Squid第四列类似`TCP_MISS/200`：前半是cache结果，后半才是HTTP状态。`TCP_MISS`不能用来标记后端不存在。
- UCB请求URL已被匿名化，方法/扩展名等少量字段仍存在，但其可学习性和真实nonmember标签都未确立；不能为了大请求数回到弱模型问题。
- ClarkNet资料的首个下载链接文字日期与文件名/measurement段有差异，应按实际日志内容核实，类似NASA七月分发文件实际止于7月28日的审计。
- UCB有版权声明保留、引用和向贡献者提供论文副本等使用条件；不会擅自用用户邮箱联系作者或发布数据。
- 任何下载都应放入新的独立空目录；解析代码放在别处、用隔离Python运行；客户端IP/用户标识不用于模型，不发布原始日志。
- 当前没有选出一个已验证、明显更大且满足全部条件的新真实工作负载。该证据缺口仍未打勾。
