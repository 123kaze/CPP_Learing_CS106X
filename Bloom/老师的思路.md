# Gama：Learned Bloom Filter 内存优化与阈值选择机制解析

# 1. 研究背景

传统 Bloom Filter（BF）是一种经典的概率型数据结构，用于集合成员查询（Membership Query）。

其特点：

* 空间效率高
* 查询速度快
* 存在假阳性（False Positive）
* 不存在假阴性（False Negative）

Bloom Filter 的误判率（FPR）与内存大小强相关。

在大规模系统中：

```text
更低 FPR
=
更大内存消耗
```

因此：

# 如何在固定内存下进一步降低 FPR

成为核心问题。

---

# 2. Learned Bloom Filter（LBF）

Learned Bloom Filter 的思想：

# 使用机器学习模型替代部分 Bloom Filter 功能

其结构如下：

```text
Query x
   ↓
ML Model
   ↓ score(x)
Threshold τ
   ↓
score(x) ≥ τ
    → 判定存在

score(x) < τ
    → 查询 backup Bloom Filter
```

其中：

* ML 模型负责“学习”集合分布
* backup BF 保证不存在假阴性

---

# 3. LBF 的核心问题：阈值选择

模型不会直接输出：

```text
存在 / 不存在
```

而会输出：

```text
score ∈ [0,1]
```

表示元素属于集合的概率。

例如：

| 元素 | Score |
| -- | ----- |
| x1 | 0.998 |
| x2 | 0.994 |
| x3 | 0.013 |

因此需要设定：

# 阈值 τ（Threshold）

用于划分：

```text
高分 → 模型直接接受
低分 → backup BF 处理
```

---

# 4. 阈值选择的本质

阈值 τ 决定：

---

## 4.1 模型误判数量

如果 τ 太低：

```text
更多负样本被模型误判
```

导致：

```text
False Positive ↑
```

---

## 4.2 Backup BF 大小

如果 τ 太高：

```text
更多正样本进入 backup BF
```

导致：

```text
Backup BF 占用内存 ↑
```

---

因此：

# τ 本质是在：

```text
模型误判
vs
backup BF 大小
```

之间寻找平衡。

---

# 5. 什么是 Prediction Score Space

模型输出的所有可能 score：

```text
[0,1]
```

整个范围称为：

# Prediction Score Space

即：

# “预测分数空间”

---

# 6. 为什么均匀划分 Score Space 是错误的

一个直观方案：

```text
0.0
0.1
0.2
...
0.9
```

作为候选阈值。

但论文发现：

# 模型分数分布极其不均匀（extremely uneven）

例如：

| 区间      | 数据量    |
| ------- | ------ |
| 0~0.1   | 500000 |
| 0.1~0.2 | 490000 |
| 0.2~0.8 | 极少     |
| 0.8~1.0 | 499990 |

大量数据会：

# 极端扎堆

---

因此：

真正最优阈值可能是：

```text
τ = 0.134271
```

但均匀划分只测试：

```text
0.1 和 0.2
```

直接错过最佳点。

---

# 7. Gama 的核心解决方案

Gama 不再：

```text
人为均匀划分 score 空间
```

而是：

# 直接使用所有真实 score 作为候选阈值

即：

```text
{τ1, τ2, τ3, ..., τn}
```

其中：

```text
τi = 模型对第 i 个样本输出的真实分数
```

---

# 8. 为什么会出现 O(n²) 问题

假设：

```text
共有 n 个样本
```

那么：

```text
共有 n 个候选阈值
```

---

若采用传统方法：

对于每个候选阈值：

1. 构建 backup BF
2. 插入所有低于阈值的元素
3. 重新统计 FPR

---

最坏情况下：

每个阈值：

```text
需要插入 n 个元素
```

因此：

# 总复杂度

O(n^2)

---

# 9. Gama 的关键优化思想

论文最核心的贡献：

# 不真实构建 backup BF

---

因为：

Bloom Filter 的 FPR 可以通过数学公式直接计算。

经典 BF FPR：

\left(1-e^{-kn/m}\right)^k

其中：

| 参数 | 含义       |
| -- | -------- |
| n  | 插入元素数    |
| m  | BF bit 数 |
| k  | hash 函数数 |

---

注意：

# FPR 仅依赖：

```text
插入元素数量 n
```

而不依赖：

```text
具体插入了哪些元素
```

---

因此：

# 无需真实构建 BF

只需统计：

```text
当前有多少元素进入 backup BF
```

即可。

---

# 10. 排序 + 滑动统计机制

Gama 的真正加速来自：

# 排序 + 增量更新

---

## Step 1：排序

将所有 score 从小到大排序：

```text
τ1 < τ2 < ... < τn
```

复杂度：

O(n\log n)

---

## Step 2：滑动 Threshold

从高阈值向低阈值滑动。

关键观察：

# Threshold 每移动一次

只会：

```text
一个元素跨过边界
```

---

## 情况 1：跨界元素是负样本

说明：

```text
模型新增一次误判
```

更新：

```text
n_M += 1
```

---

## 情况 2：跨界元素是正样本

说明：

```text
少一个元素进入 backup BF
```

更新：

```text
n_B -= 1
```

---

因此：

# 每次更新只需 O(1)

无需重新统计。

---

# 11. 复杂度优化

原始方案：

O(n^2)

Gama 优化后：

排序：

O(n\log n)

滑动统计：

O(n)

总体：

# O(n log n)

---

# 12. 贝叶斯优化（Bayesian Optimization）

Gama 进一步使用：

# 贝叶斯优化（BO）

自动寻找：

```text
learned bits
backup BF bits
boosting rounds α
threshold τ
```

的最佳组合。

---

# 13. Gama 的三大优化（Opt I ~ III）

---

# 13.1 Opt I：复用历史模型

LightGBM 是逐轮加树：

```text
Model_100
=
Model_99 + Tree_100
```

因此：

---

## 若：

```text
αj < αmax
```

直接：

# 删除后面的树

无需重新训练。

---

## 若：

```text
αj > αmax
```

直接：

# 从历史模型继续训练

无需从头训练。

---

# 13.2 Opt II：跳过中间 Threshold Search

传统方法：

```text
每轮 boosting
都做 threshold search
```

非常耗时。

---

Gama：

# 仅在目标轮 αj 做 threshold search

中间轮：

```text
只训练树
```

---

# 13.3 Opt III：修改 Observation 规则

由于跳过中间轮 threshold search：

系统无法再获得：

```text
所有轮次中的最小 FPR
```

因此：

BO 只接收：

```text
最终 αj 的 FPR
```

作为 observation。

论文证明：

即使如此，

# BO 仍然能够正确收敛

并找到最优内存分配策略。

---

# 14. Gama 的核心思想总结

Gama 的本质思想：

# 避免重复构建状态

传统方案：

```text
每个 threshold
重新构建 BF
```

Gama：

```text
只维护：
元素数量变化
```

即：

# 将结构问题转化为计数问题

这是其性能提升的根本原因。

---

# 15. 总结

Gama 的核心贡献包括：

---

## （1）真实 Score 驱动 Threshold Selection

避免均匀划分导致遗漏最优阈值。

---

## （2）数学化替代真实 BF 构建

利用 BF FPR 公式直接计算。

---

## （3）排序 + 滑动统计

将复杂度从：

O(n^2)

降低到：

O(n\log n)

---

## （4）模型训练复用

避免 LightGBM 重复训练。

---

## （5）BO 优化加速

实现高效内存分配搜索。

---

# 16. 一句话理解 Gama

# Gama 的本质：

```text
不重新构建系统，
只维护“变化量”。
```

通过：

```text
排序
计数
增量更新
数学推导
```

将原本极其昂贵的 Learned Bloom Filter 优化过程，

转化为了：

# 一个高效的动态统计问题。
