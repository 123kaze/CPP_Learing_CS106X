# 实验 13：可部署版本（只用学习期测量）与控制器的阻尼 / 阈值修正（2026-10-28）

脚本：`src/exp13_deployable.py`。表格见 `report.md` 和 `summary.json`（已合并实验 10–13）。

## 先回答"测量用的是哪段查询"

实验 12 的"Gama＋缓存"是在**整条轨迹**上测的误报流，带后见之明。本实验补了只用前 25% 学习期测量的版本：
- 误报次数按查询量线性外推到整个生命周期，隐含"负载平稳"的假设；
- 据此联合选出树数和缓存比例，只在后 75% 上评估；
- 学习期里观测到的误报少于 100 次时，用验证集估计 FPR 作先验，同实验 12。

## 结果

### 1. 学习期校准版和全程测量版几乎一样

| | 全程测量（后见之明） | 学习期校准（可部署） |
|---|---|---|
| 11 个低预算设置中的最坏 | 2.46×（Caida 128KiB 难负例漂移） | 2.46×（同一处） |
| 各设置最坏代价的中位数 | 1.40× | 1.40× |
| 各设置中位数代价 | 1.00–1.19× | 1.00–1.33× |

逐个设置看，学习期校准版的最坏代价：
- Caida：2.46 / 1.61 / 1.40 / 1.29★
- 真实轨迹：1.33 / 1.01 / 1.14 / 1.27★
- COD：1.24 / 1.20 / 9.00★（每百万次查询多约 1 次）
- Shalla：2.05 / 1.44 / 1.40 / 1.29★

差距主要出现在 Shalla 256KiB（1.40× → 2.05×）和真实轨迹 48KiB（1.00× → 1.33×）。

**结论：Gama＋缓存的主结果可以用学习期校准版，它是可部署的。** 全程测量版作为上界参照。

### 2. 控制器的阻尼和阈值修正没有用，按约定停止，转入讨论

| | 原版 | 阻尼 | 阈值 5% | 阻尼+阈值 |
|---|---:|---:|---:|---:|
| 低预算最坏相对代价 | 31.9× | 34.1× | 31.9× | 34.9× |
| 各设置最坏的中位数 | 1.80× | 1.80× | 1.80× | 1.80× |

三个变体都没有进入 3 倍以内，按约定停止，控制器转入讨论一节。

**但失败的原因和之前以为的不同，论文里要写准。** 这次最坏的那一处（Shalla 256KiB，10 万池 Zipf 0.8）并不是缓存加多了：
- 控制器最终停在 45.6%，离线版是 40%，两者相近；
- 问题在于它从 0 开始逐步加缓存，加够之前的那段时间里，热点误报一直在发生，也就是**滞后**；
- 这是一个 FPR 本来就接近 0 的负载：每百万次查询 76 次对 2.3 次，所以相对倍数很大，绝对值只有 0.0076%。

阻尼和阈值都是用来抑制"加多"的，对滞后没有帮助，所以修正无效。实验 10 里 COD 256KiB 那次（加到 19.8%，最优是 10%）才是真正的过冲。**控制器两种失败都有：低 FPR 负载上滞后，个别负载上过冲。**

### 3. 换成绝对代价看，控制器在漂移下有价值

下表是低预算设置下，所有负载里每百万次查询多出的误报的最坏值：

| 设置 | 学习期校准 | 控制器（阻尼+阈值） | learned stacked（事后最优） |
|---|---:|---:|---:|
| COD 256KiB | 6,427 | **613** | 2,507 |
| Caida 1MiB | 5,707 | **427** | 24,320 |
| Shalla 1MiB | 37,221 | **19,141** | 19,995 |
| Shalla 2MiB | 7,285 | **1,899** | 3,792 |
| 真实轨迹 64KiB | **4.8** | 105 | 382 |
| COD 1MiB | **6.7** | 53 | 320 |

学习期校准版只看前 25%，后面出现的漂移热点它看不到；控制器会跟着继续加缓存，所以在漂移负载上的绝对损失更小。反过来，在平稳负载上，控制器的滞后让它不如一次性定好比例。

全新对抗和难负例漂移在部分设置下，所有方法的绝对最坏值都在每百万次几十万的量级。这类负载谁也修不了，符合下界。

## 对论文的含义

- **主结果改用"Gama＋缓存（学习期校准）"**，可部署。最坏 2.46 倍，各设置最坏代价的中位数 1.40 倍，和后见之明版本几乎一样。
- **在线控制器转入讨论**，写成"在线调整可行，但有两种失败：低 FPR 负载上的滞后和个别负载上的过冲；它在漂移下能减少绝对损失"。阻尼和阈值无效，因为主要问题是滞后，留作未来工作。
- **实际部署的建议**："离线学习期校准 + 定期重新校准"。重新校准时只增大缓存，不需要重建（见问题定义注记 5）。这个组合没有单独测过，论文里只能作为建议，不能作为结果。

## 局限

- 学习期校准假设负载平稳，误报次数按查询量线性外推。
- 控制器的修正只试了阻尼和阈值两种。
