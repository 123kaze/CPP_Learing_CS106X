# 实验 2：重复程度 × 负例缓存（2026-10-27）

脚本：`src/exp2_repetition_cache.py`。全部表格见 `report.md`，图见 `figures/fig3`–`fig5`。

## 设置

- 预算 256KiB 和 1MiB。结构有：PLBF；PLBF＋负例缓存，缓存从同一预算里扣，分 1/2/5/10/20% 五档；PLBF+AQF；PLBF＋无限免费缓存，作为下界。10 个种子取均值。
- 负例缓存挡在整个结构前面，直接放行和 backup 产生的误报都缓存，FIFO 淘汰。每条记录取与全部 300 万成员都不冲突的最短 h1 前缀，再加 6 bit 长度字段，实测平均约 **28–29 bit/条**。这样设计在构造上保证不会误拒成员。
- 无限免费缓存：沿用纯 PLBF 的分配，再加一个无限大、不占预算的缓存，每个误报 key 只算第一次。这是任何"根据误报反馈来修正"的方案在这个分配下能达到的下界。实验 1 里那个"直接放行误报全部消除"的上界被换掉了，因为它不是真正的上界：换一种分配就能低于它。
- 负载：查询池 1 万 / 10 万 / 全部测试负例（99.96 万；其余非成员都用在训练和验证里）× {均匀, Zipf 0.8/1.1/1.5}，每组 1000 万条查询。另外四种：每个 key 只查一次；全新对抗（模型分数最高的 5 万个负例，每个只查一次）；向难负例漂移（第 t 条查询以 0.5·t/Q 的概率来自分数最高的 2 万个负例）；探测重放 10%。

## 结果

1. **重复型负载下，负例缓存几乎贴着下界。** 每种负载取网格里最好的缓存比例，FPR 只是无限免费缓存的 1.03×（256KiB 中位数）和 1.02×（1MiB 中位数），最差 1.27× 和 1.19×。和纯 PLBF 比，FPR 降了 1–3 个数量级。比如 256KiB 探测重放 10%：PLBF 是 9.50%，缓存 10% 是 0.070%，下界是 0.055%。（图 5）
2. **朴素混合 PLBF+AQF 在所有重复型负载下都输给负例缓存**，而且和纯 PLBF 差不多，甚至更差。比如 256KiB 均匀、1 万 key 的池子，每个 key 被查约 1000 次，PLBF+AQF 仍是 0.615%，因为直接放行区的误报它修不了；同样条件下缓存 1% 是 0.0006%。
3. **没有重复的负载下，所有结构都失效，这和下界的预言一致。** 每 key 只查一次时，最好的就是纯 PLBF（0.552%），缓存只会占掉内存。全新对抗下 FPR 是 10.0%（PLBF）到 16.8%（PLBF+AQF），无限免费缓存也只有 10.0%，因为没有任何反馈可用。
4. **最优缓存比例确实随负载变化。** 256KiB 下，查询池小时 1% 最好，查询池是全部测试负例、漂移或探测重放时要 10%，每 key 一次时是 0%。1MiB 下在 0–5% 之间。**但每个预算下都存在一个固定比例，在所有负载上都不太差**：256KiB 固定 10%，最差 1.27×（每 key 一次）；1MiB 固定 5%，最差 1.22×（全新对抗）。比例选错的代价倒是可能很大：256KiB 固定 1% 遇到难负例漂移会差 73×，不加缓存（0%）最差能差 983×。（图 4）
5. 最优比例大约等于"会反复出现的误报 key 数 × 29 bit ÷ 预算"。这个数据集的查询池最多 99.96 万个 key，256KiB 下纯 PLBF 的误报 key 最多约 5,700 个，约 20KB，相当于预算的 8%，所以 10% 能覆盖所有情况。

## 对照决策表

| 结果 | 本次是否出现 |
|---|---|
| 缓存在所有负载下都接近理想上界 | **是**。前提是每个预算选对一个固定比例 |
| 中等重复度下，缓存和 backup 抢内存，固定比例怎么调都明显不如最优分配 | **在这个数据集上没有出现**。固定比例最差只差 1.22–1.27 倍 |
| 全新对抗负载下所有结构都失效 | **是**。可以作为下界的实验验证 |

所以在当前数据上，主线落在第一行：机制本身不新，"learned filter 加一个大小合适的负例缓存"就够了。

## 还不能下最终结论的原因

固定比例之所以够用，是因为误报工作集最多只有约 5,700 个 key，被查询池的大小封顶了。真实系统里非成员的全集远大于 100 万，误报工作集可能比预算大得多。这时缓存会持续被冲掉，最优比例就会落到 10% 以外，第二行有可能出现。这个数据集测不到这个区间：300 万 star 里有 200 万用于训练和验证。

要验证这一点，需要一个非成员全集远大于预算能容纳的误报 key 数的数据集，例如 URL 全量、合成的可扩展负例，或者在 COD 上减少训练负例、腾出更大的查询池。
