## 运行时测的量（只来自误报反馈，草图开销计入预算）

| 量 | 怎么测 | 开销 |
|---|---|---|
| N_eff：查过的不同负 key 数 | HLL | 1KB |
| D_F：误报过的不同 key 数 | HLL | 1KB |
| Q_F：误报次数加上被缓存挡下的次数，即没有缓存时会误报的次数 | 计数器 | 8B |
| 前 256 个误报 key 占误报查询的比例（下界） | Space-Saving | 3KB |

合计约 5KB，占 256KiB 的 2%，占真实轨迹 48KiB 预算的 10.4%。

## 设计过程中修掉的三个错误（都在冒烟阶段发现）

1. **新增误报不能按比例放大。** 缓存变大时，会有更多分段被改成直接放行。我原先假设误报量按 p(f)/p 成比例增长，这在难负例漂移下会把热点的量一起放大，结果选出过小的缓存（FPR 25%）。改为加性：新增的误报只来自新改成放行的分段，按一般查询率计入。均匀和 Zipf 负载下两种写法结果相同。
2. **用 W = p·N_eff 和"不同 key 数"反推 s_F，原理上不可辨识。** N_eff 只数被查到过的 key，所以 D_F 总是约等于 W，反推出的 s 永远是 0。改成由 (Q_F, D_F, 头部占比) 三个量交替拟合 (W, s_F)。这样"每 key 只查一次"时 W 会被推到很大，模型就知道几乎没有重复。不同误报 key 少于 256 个时，头部占比恒为 1，不含信息，这时取 s=0。
3. **在线版不能把前缀的测量外推到整个生命周期。** 外推会高估重复度，而只增不减意味着多给的缓存收不回来。改为只用前缀里自洽的一对量：估得偏小，会由后面的检查点补上。检查点前密后疏，从 Q/4096 开始按 2 倍递增，之后每 Q/20 检查一次。

## 结果

1. **误报流模型（在整条轨迹上测量，带后见之明）是目前最好的选法，而且不需要事先声明 N、偏斜度范围或 Q。**
   - 11 个设置（含真实轨迹）的最坏代价在 1.03–1.83 倍之间，10 个不超过 1.5 倍；中位数 1.00–1.08 倍，COD 1MiB 是 1.19 倍，真实轨迹是 1.07–1.21 倍。
   - 难负例漂移下：Caida 256KiB 从实验 8b 的 7.5 倍降到 1.01 倍，COD 256KiB 是 1.08 倍，Shalla 1MiB 是 1.05 倍。最差的是 Caida 128KiB，为 1.83 倍。
   - 对照：固定 40% 的最坏代价在 1.3–9.5 倍之间，在真实轨迹上是 3.4–3.7 倍。
2. **只增不减的在线控制器**（只看过去，不知道未来）：
   - 中位数 1.08–1.26 倍，最坏 1.27–2.5 倍。COD 1MiB 最坏 5 倍，但绝对代价只有每百万次查询多 280 次误报。
   - 真实轨迹上分别是 1.87 倍（48KiB）、1.58 倍（64KiB）、1.17 倍（128KiB）。
   - 难负例漂移下 1.1–2.2 倍。热点是逐渐出现的，缓存的增长总要滞后一些。
   - 相对"后见之明"的误报流模型，这多出来的约 1.1–1.5 倍（中位数）就是在线的代价。
   - "改分段为直接放行"相对"同等缓存比例重新分配"的估计 FPR 比：中位数 1.004，最大 1.28，和实验前的估算一致。
3. **真实轨迹（Caida 按流、按时间顺序的 TCP 包）上，规则和控制器都没有调参。**
   - 拟合出的误报流 s_F ≈ 1.13，Q_F/D_F ≈ 8.3，属于中度偏斜、中度重复。
   - 误报流模型的代价是 1.07–1.21 倍，控制器是 1.17–1.87 倍，都明显好于固定比例。
4. **敏感性（实验 9b，针对 8b 的 N_eff 模型）**：偏斜度范围只给 [0, 0.8]、Q 偏小或偏大 4 倍，各设置的最坏代价基本不变。最大的变化是 Shalla 1MiB 在 Q 偏小 4 倍时从 1.45 倍变成 1.82 倍；Caida 256KiB 的漂移在各变体下都在 6.3–8.6 倍之间，那是 8b 模型本身的局限，误报流模型已经解决了这个问题。
5. **0–2% 之间加密网格后**，COD 1MiB 的最坏代价从 3 倍降到 1.5 倍（误报流模型）。剩下的差距来自草图本身要占 0.5% 的预算，而最优比例只有约 0.05%。

## 对论文的含义

- 贡献 2 可以写成**误报流模型**：只用误报反馈测三个量，加一个 Che-LRU 命中模型，就能定出缓存比例。它不需要声明负例全集大小和偏斜度，在合成负载和真实轨迹上都在最优的 1.5 倍以内（只有一个例外 1.83 倍）。
- 贡献 3 可以写成**只增不减的控制器**：每一步都不需要重建；测得偏小时会在后面自动补上；代价有上界，即"改放行的损失"（≤1.28 倍）乘以在线滞后，实测中位数 1.08–1.26 倍。可以写一个命题，但上界目前只是经验值。
- 负面结果，各一句：
  - 新增误报按比例缩放的模型在漂移下会失败；
  - 用不同数反推 s_F 不可辨识。

## 局限

- 合成负载 2 个种子，真实轨迹只有 1 条。
- 误报流模型的测量是在整条轨迹上做的，相当于离线标定；在线版本的代价见第 2 条。
- 极小预算下草图的开销不可忽略（48KiB 时占 10%）。
- 真实轨迹的模型特征是我们自己选的，只用了源地址、目的地址和包长统计。
