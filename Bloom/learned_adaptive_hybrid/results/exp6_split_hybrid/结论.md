# 实验 6：分工型混合与缓存写入的成员比对成本（2026-10-27）

脚本：`src/exp6_split_hybrid.py`。表格见 `report.md` 和 `summary.json`，图见 `figures/fig9`。

## 设置

- 数据集：Caida；预算：128KiB、256KiB。
- 缓存一律用 LRU，比例网格和实验 4 相同（0–80%，放不下模型的档位跳过）。
- 负载：19 种（去掉探测重放），每种 5 个种子。
- 比较四种结构：
  - **PLBF+缓存**：缓存所有误报。写入时查一次成员索引，取与全部成员都不冲突的最短前缀，约 27.5 bit/条。
  - **PLBF+缓存(二次准入)**：同一个 key 第二次误报才写入，即 SkiQF 式的"先租后买"。
  - **PLBF+缓存(64位)**：存完整的 64 位哈希，不查成员索引。成员被误拒的概率约 n/2⁶⁴，所以不是严格零漏判。
  - **PLBF+AQF+放行区缓存**（分工型）：backup 换成 AQF，自己修自己的误报；缓存只收直接放行区的误报，前缀只需避开放行区成员。
- 抽样核对：PLBF+缓存与实验 4 的 LRU 结果逐行一致。

## 结果

1. **分工型混合没有赢。** 在各自最优比例下，它的 FPR 相对 PLBF+缓存：

   | 预算 | 中位数 | 最差 | 最好 |
   |---|---:|---:|---|
   | 128KiB | 1.25× | 1.66× | 1.00×（全新对抗，持平） |
   | 256KiB | 1.38× | 2.09× | 1.09× |

   没有任何负载更好。离下界的差距也更大：128KiB 中位数 1.64×、最差 11.76×；256KiB 中位数 1.49×、最差 5.89×。PLBF+缓存对应的数字是 1.23×/9.97× 和 1.08×/2.94×。

   **原因**：低预算下 AQF 每个成员的固定开销大（每槽 r+3 bit、负载 0.95、5% 预留），分配器只好把更多分段改成直接放行。以 256KiB 为例，放行区里的测试负例从 4.5 万涨到 12.4 万。放行区的误报只有缓存能修，这部分新增的误报超过了 AQF 在 backup 上修误报省下的。所以在容量受限的区间，"backup 交给 AQF"的结构成本大于它的收益。

2. **成员比对的成本**（各自最优比例下，每百万次查询的中位数）：

   | 结构 | 每次误报的成员/反向映射查询 | 误报（/百万） |
   |---|---:|---:|
   | PLBF+缓存 | 1.0 | 500（128KiB）/ 208（256KiB） |
   | PLBF+缓存(二次准入) | 0.5 | 999 / 416 |
   | PLBF+缓存(64位) | 0 | 1,070 / 221 |
   | PLBF+AQF+放行区缓存 | 约 1.0（AQF 扩展 + 缓存写入） | 829 / 287 |

   - PLBF+缓存每次误报最多多一次成员索引查询；而误报本来就会访问一次后端，所以最坏情况是让误报事件的后端访问量翻倍。
   - **二次准入**把查询次数减半，代价是误报约翻倍，离下界的中位数从 1.08–1.23× 变成约 2×。在我们的代价模型下不划算。不过这个结论依赖成员查询和后端查询的成本之比，也就是 SkiQF 的 α，应该按 α 报告。
   - **64 位**完全不需要成员索引。中位数只差一点（256KiB 1.14× 对 1.08×），但在工作集大的负载上最差会到 9.6–13×，因为每条 64 bit 是 27.5 bit 的 2.3 倍，缓存装下的 key 少一半以上。
3. **"成员索引"是额外结构**，作用和 SkiQF 说的反向映射相同，不在过滤器的内存预算里。全部成员的有序哈希数组在 Caida 上约 9.6MB，COD 上约 24MB，可以放在磁盘上。如果后端的索引本身就按 key 哈希排序，那么误报时那次后端查询自然会落到前驱和后继之间，最短前缀可以顺带算出，不需要额外查询。这一点还没验证，只能作为讨论。

## 对论文的含义

- "放行区用缓存、backup 用 AQF"的分工型结构，在我们测的容量受限区间里不成立，**不作为贡献**。论文可以把它作为负面结果写一句："低预算下 AQF 的每成员开销会扩大直接放行区，得不偿失"。
- 缓存写入需要成员比对，必须计入成本。论文里应：
  - 引用 SkiQF，说明这一步和 adaptive filter 的反向映射查询是同类成本；
  - 报告"每次误报 ≤1 次成员查询"；
  - 把 64 位无比对版本列为"省掉成员索引、代价是工作集大时更差、且只是概率零漏判"的另一档选择。

## 局限

- 只测了 Caida 128/256KiB。高预算下 AQF 的开销占比下降，结论可能不同；实验 1 里 COD 4MiB 下 PLBF+AQF 已经是 0 误报。
- AQF 用的是抽象实现，内存比真实实现少记约 2%，对 AQF 略有利，所以"输了"的结论不受影响。
