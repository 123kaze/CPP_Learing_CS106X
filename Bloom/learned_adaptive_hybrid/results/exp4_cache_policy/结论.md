# 实验 4：差距来自比例、容量还是淘汰策略（2026-10-27）

脚本：`src/exp4_cache_policy.py`。完整表格见 `report.md`，逐策略汇总见 `summary.json`，图见 `figures/fig8`。

附带的 B 预览（离线选比例遇到负载错配时的代价）：脚本 `src/exp5_mismatch.py`，结果在 `results/exp5_mismatch/report.md`。

## 设置

- **数据和预算**：Caida，128KiB 和 256KiB，也就是实验 3 里误报工作集远大于缓存的那两档。
- **缓存比例**：0、1、2、5、10、20、40、60、80%。128KiB 下比例为 80% 时，剩下的预算放不下模型，这一档跳过。
- **淘汰策略**：
  - FIFO：实验 3 用的策略，这里作回归对照，抽样核对和实验 3 逐行一致；
  - LRU；
  - oracle-LFU：事先知道整条轨迹，只准入"总出现次数最多"的那批误报 key，填满为止，进了不淘汰；
  - OPT：Bélády 策略，淘汰下次出现最晚的 key，允许直接不收新 key。条目长度只差几 bit，按条数近似最优。
- **下界**：无限免费缓存，每个误报 key 只付第一次误报。
- **负载**：实验 3 的 20 种负载里去掉"探测重放"，因为它的查询取决于过滤器的输出，OPT 无从定义。剩下 19 种，各跑 5 个种子。
- **正确性检查**：抽样负载上 OPT ≤ LRU、FIFO，且所有策略 ≥ 下界。

## 结果：三个因素都起作用，各管不同的负载

1. **淘汰策略对漂移负载影响最大。** 256KiB 的难负例漂移，在最优比例下离下界：FIFO 5.39×，LRU 2.94×，oracle-LFU 2.47×，OPT 2.10×。只是把 FIFO 换成 LRU，差距就去掉了一大半。**以后默认用 LRU，FIFO 是一个偏弱的对照。**
2. **工作集大、重复度低的负载上，瓶颈是容量。** 128KiB 下 100 万 key 池的均匀负载，每个 key 平均出现约 10 次，连 OPT 在最优比例下也离下界 6.32×。FIFO、LRU、oracle-LFU 在这里几乎没用，最优比例下 FPR 和不加缓存差不多（图 8 第一行第 2 格）。这类负载没有任何淘汰策略能救，只能靠更多内存，而更多内存又会挤掉 backup。
3. **"比例依赖负载"不是 FIFO 带来的假象。** 四种策略下，最优比例都分布在 0% 到 40%（LRU 和 oracle-LFU 在 128KiB 还出现 60%）。每个预算下最好的固定比例，最差代价也都在 1.33–1.75× 之间：

   | 预算 | FIFO | LRU | oracle-LFU | OPT |
   |---|---|---|---|---|
   | 128KiB | 20% → 1.33× | 20% → 1.60× | 40% → 1.62× | 40% → 1.62× |
   | 256KiB | 40% → 1.75× | 40% → 1.75× | 40% → 1.75× | 40% → 1.75× |

4. **网格延伸到 60%/80% 后结论不变。** 256KiB 下 80% 从来不是最优，60% 只在 128KiB 的 LRU 和 oracle-LFU 下各出现一次。实验 3 里"截断在 40%"的担心基本解除。

## B 预览：离线按轨迹选比例，在错配下代价很大

做法：在训练负载上选出最优比例，拿到另一个测试负载上用。

| 预算 | 错配类型 | FIFO 中位数 / 最差 | LRU 中位数 / 最差 | OPT 中位数 / 最差 |
|---|---|---|---|---|
| 128KiB | 平稳 → 漂移 | 1.56× / 1.82× | 2.05× / 2.21× | 2.60× / 3.44× |
| 256KiB | 平稳 → 漂移 | 4.95× / 5.62× | 9.07× / 10.29× | 6.94× / 10.86× |
| 256KiB | 漂移 → 平稳 | 1.64× / 1.75× | 1.64× / 1.75× | 1.64× / 1.75× |
| 两个预算 | 同族换参数、换查询池大小 | 中位数 1.02–1.21× | | 最差 25–990×（几乎都来自训练负载选了 0%） |

两个要点：
- 最坏的情况几乎都是：训练负载没有重复（每个 key 只查一次、全部池均匀），于是选了 0%；部署后负载出现重复，FPR 会差几百倍。
- **离线按轨迹选比例，在错配时比"每个预算一个固定比例"更差。** 固定比例（256KiB 下 40%）对所有负载最差只差 1.75×；按平稳轨迹选出来的比例，遇到漂移会差 5–10 倍。

这个预览用的是整条轨迹作训练，不是轨迹前缀，所以代价被低估了，真实情况只会更差。

## 对论文三个贡献点的含义

- **贡献 1（刻画）**：更扎实了，要补一条。重复型负载的可修部分分两种情况：
  - 工作集小于缓存时，换任何策略都接近下界；
  - 工作集远大于缓存、重复度又低时，即使用 OPT 也离下界 6 倍以上，属于"容量受限，修不了"的第三种情形。

  所以刻画应从"重复 vs 全新"扩成三类：重复且装得下、重复但装不下、全新。
- **贡献 2（轨迹感知的联合分配）**：**原来的写法站不住。** 按某条历史轨迹去最优化比例，会对那条轨迹过拟合，一错配就比一个稳健的固定比例差得多。可以改成**稳健分配**：在一族可能的负载上取"最差情况最好"的比例。在 Caida 上，这个比例在最差负载上只差 1.6–1.75×，而且只需要知道负载族的范围，不需要精确轨迹。
- **贡献 3（在线调整）**：有存在的理由（离线选在漂移下会出大错），但**可赢的空间有限**。在这些负载上，它相对稳健固定比例最多能赢 1.33–1.75×，除非能利用同一条轨迹内部的阶段变化（比如漂移前后各用不同比例），这一点还没测。另外，往回调（缓存 → backup）要重建分段，有成本，见 `docs/问题定义.md` 注记 5。

## 局限

- 只有 Caida 一个数据集。COD 的工作集小，这三个因素在 COD 上都不重要（实验 2）。
- 比例网格是离散的；OPT 按条数近似，条目长度在 20–30 bit 之间，严格说不是最优。
- 漂移只有一种合成方式。B 的预览用整条轨迹作训练，偏乐观。
