## 记号与模型

- 全集 U，成员集 S ⊂ U，|S| = n。h : U → {0,1}^64 是理想随机哈希。
- **基础结构 B**：模型加分段 backup 过滤器（PLBF），构建后不再变化，并且 zero-FN：对所有 x ∈ S 都有 B(x) = 1。
- 分数落在"直接放行"分段的区域记为 H，n_H = |S ∩ H|。
- 静态误报集合 F = {x ∉ S : B(x) = 1}。它分成两部分：F_H = H \ S（直接放行区里的全部非成员），F_B 为 backup 过滤器的误报。
- 非成员查询序列 σ = x_1, …, x_Q。令 Q_F(σ) 为 σ 中落在 F 里的查询次数，D_F(σ) 为其中不同 key 的个数。D_H、Q_H 的定义类似，只是限定在 H 区。
- **反馈**：每个被放行的查询都会访问后端，系统因此知道它是不是成员。这和 AdaptiveQF 的设定一致。
- 纯 B 的误报次数是 FP_B(σ) = Q_F(σ)。

## 引理 1（缓存记录不会误拒成员）

对非成员 x，令 L(x) = 1 + max_{y∈S} LCP(h(x), h(y))，其中 LCP 是两个 64 位串的最长公共前缀长度。只要 h(x) 不等于任何成员的哈希，就有 L(x) ≤ 64，而且没有任何成员的哈希以 h(x) 的前 L(x) 位开头。

**证明**：按 L 的定义，每个成员与 h(x) 的公共前缀都短于 L(x)。∎

所以缓存每条记录存 (h(x) 的前 L(x) 位, L(x))，查询时比对前缀，构造上就保证 zero-FN。实现时只需在成员哈希的有序数组里找 h(x) 的前驱和后继，各算一次 LCP。

**期望长度**：n 个随机串时，E[L] = log2 n + O(1)，这是 trie 深度的经典结果（Knuth, TAOCP Vol. 3, §6.3；Szpankowski 1988）。实测 COD（n = 3×10⁶）的 L 均值是 22.8，log2 n = 21.5；Caida（n = 1.2×10⁶）的 L 均值是 21.5，log2 n = 20.2。两个数据集都是 log2 n + 1.3。每条记录再加 6 bit 长度字段，共约 28–29 bit。

## 定理 1（上界：反馈修正后的误报次数）

(a) **缓存无限大时**：B 前面加一个负例缓存，每次误报都把该 key 写入缓存（按引理 1 编码）。对任意非成员序列 σ：

  FP(σ) = D_F(σ) = D_H(σ) + D_{F_B}(σ)，

而且全程 zero-FN。

**证明**：同一个 key 第一次出现在 F 里时会误报一次，随后被写入缓存，之后它的每次出现都被缓存拒绝。不在 F 里的 key 不会误报。zero-FN 由引理 1 保证。∎

(b) **缓存容量为 k 条，采用 FIFO 或 LRU 淘汰时**：把 σ 限制在 F 上得到子序列 σ_F。FP(σ) 恰好等于 k 页 FIFO/LRU 分页算法在 σ_F 上的缺页次数。由 Sleator–Tarjan（CACM 1985）对 FIFO 和 LRU 的竞争比结论，对任意 h ≤ k：

  FP(σ) ≤ k/(k−h+1) · OPT_h(σ_F) + h，

其中 OPT_h 是容量为 h 的离线最优分页的缺页次数。并且 OPT_h(σ_F) ≥ D_F(σ)，即每个不同 key 至少缺页一次。

需要说明两点：
- 缓存记录的长度不完全相同（20–30 bit），严格说属于变长分页，Bélády 算法不再是最优的。保守做法是取 k = ⌊C / L_max⌋，C 为缓存总 bit 数。
- 上面的竞争比是相对同类缓存的最优离线策略而言，不是相对所有可能结构。

**对应实验**：图 5 的对角线就是 (a)。实验 2 中，选对比例的有限缓存与它的比值中位数 1.07，最差 1.23。

## 定理 2（下界：全新查询）

**假设（模型不可区分）**：在 H 区内，模型分数无法区分成员和非成员。形式化为：给定模型和分段，S ∩ H 是 U_H（H 区的全集，|U_H| = N_H）的一个均匀随机 n_H 元子集，并且 N_H ≫ n_H / ε。

**结论**：任何结构，只要满足以下三点：
- 状态是 S、历史查询及其反馈的函数，
- 在任意时刻占用不超过 m bit，
- 对 S zero-FN，

那么面对"每次都是没查过的、在 U_H \ S 上均匀抽取的新 key"这种查询流（"全新对抗"），每条查询的误报概率都不低于 ε，其中 ε 满足：

  m ≥ n_H · log2(1/ε) − O(n_H)，即 ε ≥ 2^{−m/n_H − O(1)}。

**证明思路**：
1. 固定第 t 步之前的状态 s，它接受的 key 集合记为 A(s)，必须包含 S ∩ H。
2. 用 Carter–Floyd–Gill–Markowsky–Wegman（1978）的计数论证：2^m 个状态，每个状态能"覆盖"的 n_H 元子集不超过 C(|A(s) ∩ U_H|, n_H) 个，而所有可能的 S ∩ H 共 C(N_H, n_H) 个。由此可得，对大多数 S，|A(s) ∩ U_H| ≥ ε N_H，其中 ε 满足上式。
3. 新查询 x_t 在 U_H \ (S ∪ {x_1, …, x_{t−1}}) 上均匀抽取。历史查询最多只占 t−1 个 key，在 N_H 很大时可以忽略，所以 P[x_t 被接受] ≥ ε − O(t / N_H)。
4. 反馈只告诉系统"已经查过的 key 是不是成员"，不改变步骤 2 的计数。∎

**含义**：对全新查询，自适应过滤器、负例缓存以及任何反馈机制，都不可能低于"把 m bit 全部用来静态过滤 H 区"所能达到的误报率。实验 2 的"全新对抗"一行与此一致：无限免费缓存的 FPR 等于纯 PLBF（256KiB 下都是 10.1%），加缓存只会挤占内存，使 FPR 变高。

**待核对**：
- 第 2 步需要写出对 S 取平均和取最坏情况两个版本。
- O(n_H) 项的常数要算出来。
- 在 U_H 有限、并且 adversary 可以从 U_H \ S 里挑分数最高的 key 时，"均匀抽取"这个假设要换成更弱的条件。

## 命题 3（缓存比例怎么选，启发式）

设总预算为 M，模型占 μ，缓存占比例 f，缓存记录平均 b̄ ≈ 29 bit。设"会再次出现的误报 key"组成的工作集大小为 W（由负载决定）。那么：

- 当 fM ≥ W·b̄ 时，误报次数接近 D_F（定理 1a），再加大缓存只会让 backup 因为内存变少而变差。
- 当 fM ≪ W·b̄ 时，缓存不断被冲掉，收益主要来自负载的偏斜程度（热点 key 能留在缓存里）。

因此最优比例 f* ≈ min(W·b̄ / M, 收益与 backup 损失的平衡点)。实验 2（COD）中，W·b̄/M 最大约 8%，所以 256KiB 下固定 10% 在所有负载上都接近最优。实验 3（Caida）专门检验 W·b̄ ≫ M 的情形。
